# Phase 4: OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** レシート画像を GCP Vision API で OCR し、非同期ジョブ + 確認画面経由で支払いを登録する。あわせて **支払い参加者の選択**と**メンバーごとの負担金額入力**を FORM / OCR 確認 / AI CHAT 確定の全入力経路で使えるようにする。Phase 1–3 の「均等割固定」を解消し、入力経路 **手動 / AI CHAT / レシート OCR** の 3 系統を完成させる。OCR 処理中は `--red` を発色(設計書 §12.3)。

**Architecture:** Frontend が画像を `POST /api/groups/{groupId}/ocr/upload` で送信 → Backend が **Supabase Storage**(`receipts` bucket)へ保存し **`ocr_jobs`** 行を `pending` で INSERT → 即 `jobId` を返却 → **`asyncio.create_task`** で同一プロセス内バックグラウンド OCR → Frontend は **2 秒間隔・最大 30 秒**で `GET /api/ocr-jobs/{id}` をポーリング → 成功時 **確認 UI**(`OcrConfirmForm`)で店名・合計に加え **MemberShareEditor** で参加者と金額を編集 → `POST /api/groups/{id}/payments` で `source=ocr` + `shares[].shareType=amount` 登録。手動 FORM も同一 **MemberShareEditor** を共有。Backend は `share_type=amount` 時に **分担合計 = payment.amount** を検証(`InvalidPaymentShares`)。Storage / Vision / DB は service 層に分離し router は HTTP I/O のみ。

**Tech Stack:** Backend 既存 + **`google-cloud-vision`**(GCP Vision API)、**Supabase Storage REST**(`httpx` + Service Role Key、または `supabase` Python SDK)、Alembic(`ocr_jobs` テーブル)、Frontend は **kubb 生成型 + client** + `<input type="file" accept="image/*">` + ポーリング hook、`--red` UI。

> **重要な落とし穴**(Phase 4 実装時に観測)
>
> - **`from datetime import datetime`(class 直接 import)を使うこと**。`import datetime`(モジュール)で受けると `from __future__ import annotations` 下で SQLAlchemy が `Mapped[datetime]` を解決できず `MappedAnnotationError` で起動失敗する。SPLAI 既存 model(`group.py` / `payment.py`)も class 直接 import に揃えている。
> - **Enum は `enum.StrEnum`(Python 3.11+)**。`(str, enum.Enum)` 二重継承は ruff `UP042` で警告される(SPLAI Phase 1 で確立した規約)。`enum.StrEnum.value` が `str` になる挙動は同等。
> - **`group_id` には `nullable=False` を明示**(SPLAI 既存 `Member.group_id` / `Payment.group_id` と整合)。SQLAlchemy の default は False だが、明示する方が読み手に親切。

```python
# backend/app/models/ocr_job.py
from __future__ import annotations

import enum
import uuid
from datetime import datetime

from sqlalchemy import DateTime, Enum, ForeignKey, String, Text, func
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.dialects.postgresql import UUID as PG_UUID
from sqlalchemy.orm import Mapped, mapped_column

from app.db.base import Base


class OcrProvider(enum.StrEnum):
    GCP_VISION = "gcp_vision"


class OcrJobStatus(enum.StrEnum):
    PENDING = "pending"
    PROCESSING = "processing"
    SUCCEEDED = "succeeded"
    FAILED = "failed"


class OcrJob(Base):
    __tablename__ = "ocr_jobs"

    id: Mapped[uuid.UUID] = mapped_column(
        PG_UUID(as_uuid=True), primary_key=True, default=uuid.uuid4
    )
    group_id: Mapped[uuid.UUID] = mapped_column(
        PG_UUID(as_uuid=True),
        ForeignKey("groups.id", ondelete="CASCADE"),
        nullable=False,
        index=True,
    )
    image_path: Mapped[str] = mapped_column(String(500), nullable=False)
    provider: Mapped[OcrProvider] = mapped_column(
        Enum(OcrProvider, name="ocr_provider"), nullable=False
    )
    status: Mapped[OcrJobStatus] = mapped_column(
        Enum(OcrJobStatus, name="ocr_job_status"), nullable=False
    )
    result_json: Mapped[dict | None] = mapped_column(JSONB, nullable=True)
    payment_id: Mapped[uuid.UUID | None] = mapped_column(
        PG_UUID(as_uuid=True), ForeignKey("payments.id", ondelete="SET NULL"), nullable=True
    )
    error_message: Mapped[str | None] = mapped_column(Text, nullable=True)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, server_default=func.now()
    )
    completed_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True), nullable=True
    )
```

> **重要な落とし穴**(Phase 4 実装時に観測)
>
> - **`client.document_text_detection(image=...)` は使わない**。`google-cloud-vision` の単一機能ヘルパー(`document_text_detection` / `text_detection` / `face_detection` …)は **`add_single_feature_methods` デコレータで実行時に動的注入**される。Pylint / Pylance は静的解析できず `E1101 no-member` を出す。
> - **代わりに proto から静的に生成された `batch_annotate_images(requests=[...])` を使う**。`Feature(type_=Feature.Type.DOCUMENT_TEXT_DETECTION)` を明示する形になり、IDE 補完と静的解析の両方が通る。
> - 抑制で済ませたい場合は行末に `# pylint: disable=no-member  # noqa: E1101` を付けるか、`pyproject.toml` `[tool.pylint.typecheck] generated-members = ["google.cloud.vision.*"]` を追加。SPLAI は ruff ベースなので警告は IDE 由来 → コードを直す方を採る。

```python
# backend/app/services/ocr_gateway.py
from __future__ import annotations

import json
import re
from dataclasses import dataclass

from google.cloud import vision

from app.config import get_settings
from app.exceptions.domain import OCRFailed


@dataclass(frozen=True)
class OcrParseResult:
    merchant_name: str | None
    total_amount: int | None
    raw_text: str


def parse_receipt_text(raw_text: str) -> OcrParseResult:
    """GCP Vision の full_text から店名・合計額をヒューリスティック抽出(MVP)。

    Phase 4 は regex ベース。精度不足は Phase 5 で改善。
    """
    lines = [ln.strip() for ln in raw_text.splitlines() if ln.strip()]
    merchant_name = lines[0] if lines else None

    total_amount: int | None = None
    for line in reversed(lines):
        m = re.search(r"(?:合計|総計|total|￥|¥)\s*([0-9,]+)", line, re.I)
        if m:
            total_amount = int(m.group(1).replace(",", ""))
            break

    return OcrParseResult(
        merchant_name=merchant_name,
        total_amount=total_amount,
        raw_text=raw_text,
    )


def run_gcp_vision_ocr(image_bytes: bytes) -> OcrParseResult:
    settings = get_settings()
    if not settings.gcp_vision_credentials_json:
        raise OCRFailed("GCP_VISION_CREDENTIALS_JSON is not configured")

    client = vision.ImageAnnotatorClient.from_service_account_info(
        json.loads(settings.gcp_vision_credentials_json)
    )
    request = vision.AnnotateImageRequest(
        image=vision.Image(content=image_bytes),
        features=[vision.Feature(type_=vision.Feature.Type.DOCUMENT_TEXT_DETECTION)],
    )
    batch = client.batch_annotate_images(requests=[request])
    response = batch.responses[0]

    if response.error.message:
        raise OCRFailed(response.error.message)

    raw = response.full_text_annotation.text if response.full_text_annotation else ""
    if not raw.strip():
        raise OCRFailed("no text detected in receipt image")

    return parse_receipt_text(raw)
```

```python
# backend/app/services/storage.py
from __future__ import annotations

from uuid import UUID

import httpx

from app.config import get_settings
from app.exceptions.domain import OCRFailed

BUCKET = "receipts"
MAX_BYTES = 10 * 1024 * 1024  # 10MB


async def upload_receipt_image(
    *,
    group_id: UUID,
    job_id: UUID,
    content_type: str,
    data: bytes,
) -> str:
    if len(data) > MAX_BYTES:
        raise OCRFailed("image exceeds 10MB limit")
    if content_type not in {"image/jpeg", "image/png", "image/webp"}:
        raise OCRFailed(f"unsupported content type: {content_type}")

    settings = get_settings()
    if not settings.supabase_url or not settings.supabase_service_role_key:
        raise OCRFailed("Supabase storage is not configured")

    ext = {"image/jpeg": "jpg", "image/png": "png", "image/webp": "webp"}[content_type]
    object_path = f"{group_id}/{job_id}.{ext}"
    url = f"{settings.supabase_url.rstrip('/')}/storage/v1/object/{BUCKET}/{object_path}"

    async with httpx.AsyncClient(timeout=30.0) as client:
        res = await client.post(
            url,
            content=data,
            headers={
                "Authorization": f"Bearer {settings.supabase_service_role_key}",
                "Content-Type": content_type,
                "x-upsert": "true",
            },
        )
    if res.status_code >= 400:
        raise OCRFailed(f"storage upload failed: {res.status_code} {res.text[:200]}")

    return f"{BUCKET}/{object_path}"


async def download_receipt_image(storage_path: str) -> bytes:
    settings = get_settings()
    url = f"{settings.supabase_url.rstrip('/')}/storage/v1/object/{storage_path}"
    async with httpx.AsyncClient(timeout=30.0) as client:
        res = await client.get(
            url,
            headers={"Authorization": f"Bearer {settings.supabase_service_role_key}"},
        )
    if res.status_code >= 400:
        raise OCRFailed(f"storage download failed: {res.status_code}")
    return res.content
```

**Files:**

- Create: `backend/tests/test_ocr_jobs_service.py`

#### 設計の要点

1. **`run_job` は API リクエスト終了後にバックグラウンドで走る** ため、リクエストスコープの DB session(`Depends(get_session)`)は使えない(ハンドラ復帰時に close 済み)。`run_job` 自身が `SessionLocal()` から **新しいセッション**を開く。
2. **トランザクションを 2 段階に分割** — 「`pending → processing` を確定」→ 重い OCR 実行 → 「結果を反映」。1 本の長いトランザクションにすると DB 行ロックが OCR 中も保持され、ポーリング read を阻害する可能性がある。
3. **Vision SDK は同期 (blocking)** — `asyncio.to_thread(ocr_gateway.run_gcp_vision_ocr, image_bytes)` でスレッドにオフロードして event loop を塞がない。Storage 側 (`storage.download_receipt_image`) は `httpx.AsyncClient` ベースなので素直に `await`。
4. **`result_json` は snake_case で DB に保存**(conventions §8.4)。camelCase 変換は API 層 (`OcrResultDTO` Pydantic with `alias_generator=to_camel`) が担う。DB に camelCase を入れると Python 側で `result["merchant_name"]` と書けず一貫性が崩れる。
5. **例外は `run_job` 内で握って `failed` に倒す** — `asyncio.create_task` の中で raise した例外は default で sink され、Task が GC されるまでログにも残らない。`OCRFailed` / `httpx.HTTPError` / 想定外の `Exception` をすべて catch して `error_message` に記録する。
6. **Idempotency** — `run_job(job_id)` を二重起動した場合の保護は MVP では追加しない(`asyncio.create_task` 1 回しか呼ばないため)。Phase 5 で外部 worker 化する際に row-level lock を入れる前提。

#### `result_json` の DB 形式 (snake_case)

```python
{
    "merchant_name": "居酒屋A",
    "total_amount": 12000,
    "raw_text": "...",
}
```

API 応答 (`OcrResultDTO`, Task 6) が `merchantName` / `totalAmount` / `rawText` に自動変換。

```python
# backend/app/services/ocr_jobs.py
from __future__ import annotations

import asyncio
import logging
from datetime import datetime, timezone
from uuid import UUID

from sqlalchemy.ext.asyncio import AsyncSession

from app.db.session import SessionLocal  # 既存 helper 名に合わせて調整
from app.exceptions.domain import OCRFailed
from app.models.ocr_job import OcrJob, OcrJobStatus, OcrProvider
from app.services import ocr_gateway, storage

logger = logging.getLogger(__name__)

_ERROR_MESSAGE_MAX = 1000


async def create_job(
    db: AsyncSession,
    *,
    group_id: UUID,
    image_path: str,
    provider: OcrProvider = OcrProvider.GCP_VISION,
    job_id: UUID | None = None,
) -> OcrJob:
    """`pending` 状態の ocr_jobs 行を作成する。コミットは呼び出し側責務。

    `job_id` を指定すると行 PK を採用する(API 層で **upload より前に UUID を採番**し、
    Storage path `receipts/{group_id}/{job_id}.{ext}` と DB 行で同一 ID を使うため)。
    省略時は SQLAlchemy default(`uuid.uuid4`)に任せる(直接呼ぶ場合の利便性)。
    """
    kwargs: dict = {
        "group_id": group_id,
        "image_path": image_path,
        "provider": provider,
        "status": OcrJobStatus.PENDING,
    }
    if job_id is not None:
        kwargs["id"] = job_id
    job = OcrJob(**kwargs)
    db.add(job)
    await db.flush()  # id / created_at を populate
    return job


async def get_job(db: AsyncSession, job_id: UUID) -> OcrJob | None:
    return await db.get(OcrJob, job_id)


async def run_job(job_id: UUID) -> None:
    """バックグラウンド OCR パイプライン。

    `asyncio.create_task(run_job(...))` で起動される前提。
    リクエストスコープ session を持たないので独自に `SessionLocal` を開く。
    """
    # Phase 1: pending → processing
    if not await _transition_to_processing(job_id):
        return  # job が存在しない or すでに進行中

    # Phase 2: 重い処理(別トランザクション)
    try:
        image_path = await _load_image_path(job_id)
        if image_path is None:
            return
        image_bytes = await storage.download_receipt_image(image_path)
        # Vision SDK は同期 → スレッドにオフロード
        parsed = await asyncio.to_thread(
            ocr_gateway.run_gcp_vision_ocr, image_bytes
        )
        await _mark_succeeded(
            job_id,
            result={
                "merchant_name": parsed.merchant_name,
                "total_amount": parsed.total_amount,
                "raw_text": parsed.raw_text,
            },
        )
        logger.info("ocr_job %s succeeded", job_id)
    except OCRFailed as exc:
        await _mark_failed(job_id, str(exc))
        logger.warning("ocr_job %s failed: %s", job_id, exc)
    except Exception as exc:
        # asyncio.create_task の例外 sink を回避:必ず DB に痕跡を残す
        await _mark_failed(job_id, f"unexpected error: {exc!r}")
        logger.exception("ocr_job %s crashed", job_id)


# ---- internal helpers -------------------------------------------------

async def _transition_to_processing(job_id: UUID) -> bool:
    async with SessionLocal() as db:
        job = await db.get(OcrJob, job_id)
        if job is None:
            logger.warning("ocr_job %s not found", job_id)
            return False
        if job.status != OcrJobStatus.PENDING:
            logger.info("ocr_job %s already %s, skipping", job_id, job.status)
            return False
        job.status = OcrJobStatus.PROCESSING
        await db.commit()
        return True


async def _load_image_path(job_id: UUID) -> str | None:
    async with SessionLocal() as db:
        job = await db.get(OcrJob, job_id)
        return job.image_path if job else None


async def _mark_succeeded(job_id: UUID, *, result: dict) -> None:
    async with SessionLocal() as db:
        job = await db.get(OcrJob, job_id)
        if job is None:
            return
        job.result_json = result
        job.status = OcrJobStatus.SUCCEEDED
        job.completed_at = datetime.now(timezone.utc)
        await db.commit()


async def _mark_failed(job_id: UUID, message: str) -> None:
    async with SessionLocal() as db:
        job = await db.get(OcrJob, job_id)
        if job is None:
            return
        job.status = OcrJobStatus.FAILED
        job.error_message = message[:_ERROR_MESSAGE_MAX]
        job.completed_at = datetime.now(timezone.utc)
        await db.commit()
```

> **Sessionmaker 利用上の注意:**
>
> - `app/db/session.py` の `SessionLocal`(=`async_sessionmaker(engine, expire_on_commit=False)`)を **直接呼ぶ**。同ファイルにある `get_session()` は `yield` する async generator で **FastAPI `Depends()` 専用**(リクエストスコープ用)。background task からは context manager として使えないため、必ず `SessionLocal()` を選ぶこと。
> - Phase 1 の `payments.py` / `groups.py` は全部 `Depends(get_session)` 経由なので、本 service が **初の `SessionLocal` 直接利用例**になる。

#### API 契約(設計書 §7 準拠)

| Method | Path                                | Auth                                                            | Body                                                              | 成功 Response                                         | 主な失敗                                                                    |
| ------ | ----------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------- |
| POST   | `/api/groups/{group_id}/ocr/upload` | `X-Member-Id` 必須(`require_member` が path の group_id と照合) | `multipart/form-data`: `file` (image/jpeg \| png \| webp, ≤ 10MB) | `201 { jobId }`                                       | `400`(content-type / size / 空), `401`(MemberMismatch), `502`(Storage 失敗) |
| GET    | `/api/ocr-jobs/{job_id}`            | 不要(read op、design.md §2)                                     | —                                                                 | `200 { id, groupId, status, result?, errorMessage? }` | `404`(job not found)                                                        |

> **URL は SPLAI の path 規約に揃える** — `/api/groups/{group_id}/payments` / `/settlement` / `/members` 等と同じく **`group_id` を path に置く**ことで `app/auth/deps.py:require_member`(`group_id: UUID` を path から読む契約)を再利用できる。`/api/ocr/upload` のように Form で `groupId` を渡す形にすると `require_member` の `group_id` が解決できず 422 になる。

#### 設計の要点

1. **UUID 先行採番** — Storage path = `receipts/{group_id}/{job_id}.{ext}`。`uuid4()` を **upload と DB INSERT の前に**生成し両方に渡す。後から `image_path` を UPDATE する 2-write 方式は競合・整合性で不利。Task 5 で `create_job(job_id=...)` を許容済み。
2. **Storage upload → DB INSERT → commit → create_task の順序固定** — この順番で「DB 行が存在 ⟹ `image_path` が指すファイルが必ず存在」という invariant を保つ。`create_job` は `flush()` のみで未 commit、`await db.commit()` で確定 → そのあと `asyncio.create_task` を起動するので background 側(別 session)で行が見える。逆順(commit 先行)は `image_path` 不正な行を `run_job` が拾うリスクを生む。Storage 成功 + commit 失敗のみ orphan file が残るが、Phase 5 の 24h cleanup cron で回収する前提。
3. **認可は `Depends(require_member)` 一本に集約** — `require_member` が path の `group_id` と `X-Member-Id` を SQL で突き合わせて `MemberMismatch` を投げる。本ハンドラ内に手動の `requester.group_id != group_id` 検証は **書かない**(重複 + 漏れの温床)。
4. **content-type / size の早期検証** — `_ALLOWED_CONTENT_TYPES` / `_MAX_UPLOAD_BYTES` を api/ocr.py の private 定数に置き、validation で `400` 早期 return。`storage.upload_receipt_image` 側にも同等の defensive check が残る(2 重防御)。
5. **`result_json` → `OcrResultDTO`** — DB は snake_case JSONB (`{merchant_name, total_amount, raw_text}`)、API は CamelModel 経由で camelCase に。Pydantic は dict を自動マッピングしないため `OcrResultDTO(**job.result_json)` で明示変換。
6. **404 はドメイン例外** — `app/exceptions/domain.py` に `OcrJobNotFound` を追加して `GroupNotFound` 等と同パターン(middleware が ProblemDetail にマップ)。
7. **`python-multipart` 依存** — `UploadFile` を使う初の endpoint なので `uv add python-multipart` が必要(未インストールだと FastAPI が起動時 `RuntimeError`)。

```python
    認可は `Depends(require_member)` が path の `group_id` と `X-Member-Id` を
    照合して完了させる(`MemberMismatch` を内部で投げる)。本ハンドラでは
    content-type / size 検証 → Storage upload → DB INSERT → background OCR 起動のみ。
    """
    if file.content_type not in _ALLOWED_CONTENT_TYPES:
        raise HTTPException(
            status_code=400,
            detail=f"unsupported content type: {file.content_type}",
        )
    data = await file.read()
    if not data:
        raise HTTPException(status_code=400, detail="empty file")
    if len(data) > _MAX_UPLOAD_BYTES:
        raise HTTPException(status_code=400, detail="image exceeds 10MB limit")

    # UUID 先行採番:Storage path と DB 行で同一 UUID を共有する。
    job_id = uuid4()
    storage_path = await storage.upload_receipt_image(
        group_id=group_id,
        job_id=job_id,
        content_type=file.content_type,
        data=data,
    )

    job = await ocr_jobs_service.create_job(
        db,
        job_id=job_id,
        group_id=group_id,
        image_path=storage_path,
        provider=OcrProvider.GCP_VISION,
    )
    await db.commit()

    # 必ず commit 後に create_task(逆順だと "_transition_to_processing → False" で死ぬ)
    asyncio.create_task(ocr_jobs_service.run_job(job_id))
    logger.info("ocr_job %s created (group=%s)", job_id, group_id)

    return OcrUploadResponse(job_id=job.id)


@router.get("/ocr-jobs/{job_id}", response_model=OcrJobResponse)
async def get_ocr_job(
    job_id: UUID,
    db: AsyncSession = Depends(get_session),
) -> OcrJobResponse:
    """ジョブ状態 + 結果(あれば)/ エラー(あれば)を返す。認証不要(read op)。"""
    job = await ocr_jobs_service.get_job(db, job_id)
    if job is None:
        raise OcrJobNotFound(f"ocr_job {job_id} not found")

    result = OcrResultDTO(**job.result_json) if job.result_json else None
    return OcrJobResponse(
        id=job.id,
        group_id=job.group_id,
        status=job.status,  # StrEnum → Literal validator OK
        result=result,
        error_message=job.error_message,
    )
```

```typescript
// frontend/features/payments/utils/shares.ts
export type MemberShareRow = {
  memberId: string;
  name: string;
  included: boolean;
  amount: number;
};

export function sumIncludedAmounts(rows: MemberShareRow[]): number {
  return rows.filter((r) => r.included).reduce((sum, r) => sum + r.amount, 0);
}

/** 合計 amount を included メンバーに均等割(端数は先頭へ)。 */
export function distributeEqual(
  total: number,
  rows: MemberShareRow[],
): MemberShareRow[] {
  const included = rows.filter((r) => r.included);
  if (included.length === 0) return rows;
  const base = Math.floor(total / included.length);
  const remainder = total - base * included.length;
  let firstApplied = false;
  return rows.map((r) => {
    if (!r.included) return { ...r, amount: 0 };
    const extra = !firstApplied ? remainder : 0;
    firstApplied = true;
    return { ...r, amount: base + extra };
  });
}

export function toAmountShareInputs(rows: MemberShareRow[]) {
  return rows
    .filter((r) => r.included && r.amount > 0)
    .map((r) => ({
      memberId: r.memberId,
      shareType: "amount" as const,
      shareValue: r.amount,
    }));
}
```

- [ ] **Step 4: `MemberShareEditor` コンポーネント実装**

> **設計の要点:**
>
> - **Controlled component**:`rows` 状態は親が保持し、本コンポーネントは UI 描画と編集イベントのみ。これで `PaymentForm` / `OcrConfirmForm` から同じ rows 形を共有できる。
> - **Brand 規則**:`--red` は **AI アクティブ時専用**(設計書 §12.3)。合計不一致の警告は `text-ink`(墨色)で表示する。`text-red` / `bg-red` は使わない。
> - **「均等にわる」は副作用ボタン**:現在の `paymentAmount` を included メンバーに `distributeEqual` で再配分する純粋な on-click 動作。`paymentAmount` 変更時に **自動再配分はしない**(ユーザーが手で編集中の値を破壊しないため)。再配分したいときはユーザーが明示的にボタンを押す。
> - **`included` のトグル**:OFF にしたら `amount=0` に強制(分担合計に乗らない)。ON に戻したときは 0 のまま(再度ボタンで均等分配)。
> - **空入力の扱い**:数値 input が空文字のとき `Number.parseInt` は `NaN` を返すので `|| 0` でフォールバック。`step=1`、`min=0`、`inputMode="numeric"` でモバイルキーボードを数字に。

```tsx
// frontend/features/payments/components/member-share-editor.tsx
"use client";

import {
  distributeEqual,
  sumIncludedAmounts,
  type MemberShareRow,
} from "@/features/payments/utils/shares";

type Props = {
  rows: MemberShareRow[];
  onChange: (next: MemberShareRow[]) => void;
  paymentAmount: number;
};

export function MemberShareEditor({ rows, onChange, paymentAmount }: Props) {
  const total = sumIncludedAmounts(rows);
  const diff = total - paymentAmount;
  const matched = diff === 0;
  const includedCount = rows.filter((r) => r.included).length;

  const setRow = (idx: number, patch: Partial<MemberShareRow>) => {
    onChange(rows.map((r, i) => (i === idx ? { ...r, ...patch } : r)));
  };

  const equalize = () => {
    onChange(distributeEqual(paymentAmount, rows));
  };

  return (
    <fieldset className="border-t pt-3 mt-3">
      <legend className="text-sm font-medium">負担金額</legend>

      <ul className="divide-y">
        {rows.map((row, idx) => (
          <li key={row.memberId} className="flex items-center gap-3 py-2">
            <label className="flex items-center gap-2 flex-1 min-w-0">
              <input
                type="checkbox"
                checked={row.included}
                onChange={(e) =>
                  setRow(idx, {
                    included: e.target.checked,
                    amount: e.target.checked ? row.amount : 0,
                  })
                }
              />
              <span className="truncate">{row.name}</span>
            </label>

            <input
              type="number"
              inputMode="numeric"
              min={0}
              step={1}
              value={row.amount}
              disabled={!row.included}
              onChange={(e) =>
                setRow(idx, {
                  amount: Number.parseInt(e.target.value, 10) || 0,
                })
              }
              aria-label={`${row.name} の負担額`}
              className="w-28 text-right border rounded px-2 py-1 disabled:bg-bone disabled:text-stone"
            />
            <span className="text-sm">円</span>
          </li>
        ))}
      </ul>

      <div className="flex items-center justify-between mt-3">
        <button
          type="button"
          onClick={equalize}
          disabled={includedCount === 0}
          className="text-sm underline disabled:no-underline disabled:text-stone"
        >
          均等にわる
        </button>

        <p className="text-sm">
          合計 ¥{total.toLocaleString()} / 支払額 ¥
          {paymentAmount.toLocaleString()}
          {!matched && (
            <span className="ml-2 text-ink font-medium">
              (
              {diff > 0
                ? `${diff.toLocaleString()} 円超過`
                : `${(-diff).toLocaleString()} 円不足`}
              )
            </span>
          )}
          {includedCount === 0 && (
            <span className="ml-2 text-ink font-medium">
              (参加者を 1 人以上選択)
            </span>
          )}
        </p>
      </div>
    </fieldset>
  );
}
```

> **変更方針:**
>
> - **Phase 1 の「均等割固定」を撤去**:`shares: members.map(m => ({ memberId, shareType: 'equal', shareValue: 1 }))` 相当のロジックを削除し、`rows` 状態 + `MemberShareEditor` に置換。

> - **submit 可否**:`isShareEditorValid(rows, amount)` が false のあいだ submit ボタンを disabled。Backend 側 `InvalidPaymentShares`(Step 2)で同じ条件を再検証する 2 重防御。
> - **`createPayment` 呼び出し**:`shares: toAmountShareInputs(rows)`(`shareType=amount`)。`equal` リテラルは送らない。

> **`useActionState` との統合方針:**
>
> - **検証ロジックは action の中**に置く(`isShareEditorValid` を含む)。`<button disabled>` だけに頼ると DevTools で外せば bypass できるので、`createPayment` を呼ぶ手前で必ず再検証する。
> - 外側の `disabled` は **UX 専用**(無効状態の click を未然に防ぎ、submit 中 `isPending` で 2 度押し防止)。
> - 入力値はすべて **controlled state**(`description` / `payerId` / `amount` / `rows`)で持ち、action は closure 経由でそれらを読む。`FormData` は使わなくて構わない(`useActionState` の `isPending` / `state` だけが目的)。
> - エラーは `useActionState` の戻り値 `state.error` に集約し、フォーム下部に `text-ink` で表示する(`--red` は使わない)。

```tsx
// frontend/features/payments/components/payment-form.tsx — 関連部分のみ抜粋
"use client";

import { useActionState, useState } from "react";
import { createPayment } from "@/features/payments/api"; // 既存 wrapper
import {
  buildInitialRows,
  isShareEditorValid,
  toAmountShareInputs,
  type MemberShareRow,
} from "@/features/payments/utils/shares";
import { MemberShareEditor } from "./member-share-editor";

type Member = { id: string; name: string };

type Props = {
  groupId: string;
  /** X-Member-Id ヘッダ用(localStorage から `useMemberId` で取得して親が渡す)。 */
  memberId: string;
  members: Member[];
  /** AI CHAT が確定した draft(任意)。shareMemberIds があれば初期 included を絞る。 */
  draft?: {
    description?: string;
    amount?: number;
    payerId?: string;
    shareMemberIds?: string[];
  } | null;
  onCreated?: () => void;
};

type FormState = { error: string | null };

export function PaymentForm({
  groupId,
  memberId,
  members,
  draft,
  onCreated,
}: Props) {
  const [description, setDescription] = useState(draft?.description ?? "");
  const [payerId, setPayerId] = useState(
    draft?.payerId ?? members[0]?.id ?? "",
  );
  const [amount, setAmount] = useState<number>(draft?.amount ?? 0);
  const [rows, setRows] = useState<MemberShareRow[]>(() =>
    buildInitialRows(
      members,
      draft?.amount ?? 0,
      draft?.shareMemberIds ?? null,
    ),
  );

  const [state, formAction, isPending] = useActionState<FormState, FormData>(
    async (_prevState, _formData) => {
      // --- 検証は **必ず** action 内で実施(disabled は UX のみ、契約は action) ---
      const trimmedDescription = description.trim();
      if (!trimmedDescription) {
        return { error: "内容を入力してください" };
      }
      if (!payerId) {
        return { error: "支払者を選択してください" };
      }
      if (amount <= 0) {
        return { error: "金額は 1 円以上で入力してください" };
      }
      if (!isShareEditorValid(rows, amount)) {
        return {
          error:
            "分担合計が支払額と一致しません(参加者を 1 人以上選び、合計を支払額に揃えてください)",
        };
      }

      // --- 登録 ---
      // createPayment は kubb wrapper:
      //   createPayment(groupId: string, memberId: string, input: CreatePaymentRequest)
      // input は OpenAPI 由来の生成型 `{ payerId, amount, description?, paidAt?, shares }`。
      try {
        await createPayment(groupId, memberId, {
          payerId,
          amount,
          description: trimmedDescription,
          shares: toAmountShareInputs(rows),
        });
        onCreated?.();
        return { error: null };
      } catch (e) {
        return {
          error: e instanceof Error ? e.message : "登録に失敗しました",
        };
      }
    },
    { error: null },
  );

  // UX 用:無効状態を視覚的に示し、二度押しも防ぐ。validation の真の関門は action 側。
  const sharesValid = isShareEditorValid(rows, amount);
  const canSubmit =
    sharesValid &&
    description.trim().length > 0 &&
    payerId !== "" &&
    amount > 0;

  return (
    <form action={formAction}>
      {/* description input(controlled) */}
      <input
        type="text"
        value={description}
        onChange={(e) => setDescription(e.target.value)}
        placeholder="例:居酒屋"
      />

      {/* payer select(controlled) */}
      <select value={payerId} onChange={(e) => setPayerId(e.target.value)}>
        {members.map((m) => (
          <option key={m.id} value={m.id}>
            {m.name}
          </option>
        ))}
      </select>

      <input
        type="number"
        inputMode="numeric"
        min={1}
        step={1}
        value={amount}
        onChange={(e) => setAmount(Number.parseInt(e.target.value, 10) || 0)}
      />

      <MemberShareEditor
        rows={rows}
        onChange={setRows}
        paymentAmount={amount}
      />

      {state.error && (
        <p role="alert" className="text-ink text-sm mt-2">
          {state.error}
        </p>
      )}

      <button type="submit" disabled={!canSubmit || isPending}>
        {isPending ? "登録中…" : "登録"}
      </button>
    </form>
  );
}
```

> **なぜ controlled state + action 内検証なのか:**
>
> - `MemberShareEditor` は `rows` と `paymentAmount` を **そのときの React state** から表示する(合計 / 支払額 / 警告)。FormData ベースだと editor が自分の state を別管理することになり、二重管理が発生する。
> - `useActionState` の `isPending` は `<button>` のスピナー表示と多重 submit 防止に活きる。これだけで `useTransition` を別途使う必要がなくなる。
> - action は React 19 で **自動 transition 化**されるため、入力中の他フィールド更新が action 完了を阻害しない。

> **AI CHAT draft 連携(Phase 3 互換性):**
>
> - `draft.shareMemberIds` の有無で初期 `included` が切り替わる。AI が「A と B で割って」と言ったら A, B のみ ON で初期化される(C は OFF だが、ユーザーが手で ON に戻すことは可能)。

> **`paymentAmount` 変更時の挙動:** 自動再配分しない。ユーザーが金額を変えたら editor 側の合計とのズレが警告として表示され、必要なら「均等にわる」ボタンで揃える。これは **Task 11 OcrConfirmForm の挙動** と一致(設計書 §6.4.1 / §6.4.2)。

#### 設計の要点

1. **OCR 経路でも同じ POST `/api/groups/{group_id}/payments`** — body に optional `ocrJobId` を追加するだけ。新 endpoint は作らない。Frontend 側は手動 / OCR どちらでも `createPayment` 呼び出しが共通化される。

2. **状態検証(succeeded のみ accept)** — `OcrJob.status != SUCCEEDED` で payment を作ると、結果未確定の job を確定 payment と紐付けてしまう不整合が起きる。`OcrJobNotReady` を 400 で返す。

3. **group 一致検証** — `ocr_job.group_id != path の group_id` の場合 `OcrJobMismatch` を 400 で返す。攻撃 / バグで他 group の job を別 group の帳簿に混ぜないため。

4. **重複防止(`payment_id IS NOT NULL` の job は再使用不可)** — モバイルで confirm 二度押しや再送信が起きやすい。`ocr_job.payment_id` が既に設定されている場合は `OcrJobAlreadyLinked` を 409 で返す。Frontend は 409 を「既に登録済み」として扱い、確認画面を閉じる。

5. **同一トランザクションで双方向 link** — payment INSERT + flush で id を取得 → `ocr_job.payment_id = payment.id` UPDATE → commit。順序を逆にすると payment.id が null。SPLAI 既存の `create_payment_with_shares` は内部で `await db.commit()` + `db.refresh()` を行っているので、この内部に取り込む。

6. **payment.ocr_image_path は job.image_path のコピー** — 将来 `ocr_jobs` を 24h で削除しても、payment 側に Storage path が残るので画像参照を失わない(Phase 5 cleanup と独立)。

7. **camelCase wire format** — body は `ocrJobId`(`alias_generator=to_camel`)、Python 内部は snake_case `ocr_job_id`。SPLAI 規約 §8.4。

```python
# backend/app/services/payments.py
from app.exceptions.domain import (
    InvalidPaymentShares,
    OcrJobAlreadyLinked,
    OcrJobMismatch,
    OcrJobNotReady,
)
from app.models.ocr_job import OcrJob, OcrJobStatus


async def create_payment_with_shares(
    db: AsyncSession,
    *,
    group_id: UUID,
    payer_id: UUID,
    amount: int,
    description: str,
    paid_at: datetime | None,
    shares: list[ShareInputDTO],
    ocr_job_id: UUID | None = None,  # ← 追加
) -> tuple[Payment, list[PaymentShare]]:
    """支払い + shares を 1 トランザクションで作成する。

    `ocr_job_id` が指定されていれば:
      - status=succeeded、group 一致、未 link を検証
      - payment.source=ocr、ocr_image_path=job.image_path
      - 同一 tx で ocr_job.payment_id = payment.id を更新
    """

    # ── 既存:メンバー所属 + amount shares 合計の検証 ──
    member_ids = {s.member_id for s in shares} | {payer_id}
    rows = await db.scalars(
        select(Member.id).where(Member.group_id == group_id, Member.id.in_(member_ids))
    )
    amount_shares = [s for s in shares if s.share_type == "amount"]
    if amount_shares and len(amount_shares) == len(shares):
        share_total = sum(int(s.share_value) for s in amount_shares)
        if share_total != amount:
            raise InvalidPaymentShares(
                f"share amounts sum {share_total} does not match payment amount {amount}"
            )
    valid_ids = set(rows.all())
    invalid = member_ids - valid_ids
    if invalid:
        raise InvalidPaymentShares(
            f"members {sorted(map(str, invalid))} are not in group {group_id}"
        )

    # ── 新規:OcrJob 検証 + ロード ──
    ocr_job: OcrJob | None = None
    if ocr_job_id is not None:
        ocr_job = await db.get(OcrJob, ocr_job_id)
        if ocr_job is None:
            # OcrJob 不在は OcrJobNotReady で 400(404 にしない:存在しない id を投げられた状況も同じく不正)
            raise OcrJobNotReady(f"ocr_job {ocr_job_id} not found")
        if ocr_job.group_id != group_id:
            raise OcrJobMismatch(
                f"ocr_job {ocr_job_id} belongs to group {ocr_job.group_id}, not {group_id}"
            )
        if ocr_job.status != OcrJobStatus.SUCCEEDED:
            raise OcrJobNotReady(
                f"ocr_job {ocr_job_id} is {ocr_job.status}, not succeeded"
            )
        if ocr_job.payment_id is not None:
            raise OcrJobAlreadyLinked(
                f"ocr_job {ocr_job_id} already linked to payment {ocr_job.payment_id}"
            )

    # ── payment INSERT(source / ocr_image_path をここで決める) ──
    payment = Payment(
        group_id=group_id,
        payer_id=payer_id,
        amount=amount,
        description=description,
        paid_at=paid_at or datetime.now(tz=UTC),
        source=PaymentSource.OCR if ocr_job else PaymentSource.MANUAL,
        ocr_image_path=ocr_job.image_path if ocr_job else None,
    )
    db.add(payment)
    await db.flush()  # payment.id を populate

    # ── shares INSERT ──
    share_models = [
        PaymentShare(
            payment_id=payment.id,
            member_id=s.member_id,
            share_type=ShareType(s.share_type),
            share_value=s.share_value,
        )
        for s in shares
    ]
    db.add_all(share_models)

    # ── 双方向 link:ocr_job.payment_id = payment.id ──
    if ocr_job is not None:
        ocr_job.payment_id = payment.id

    await db.commit()
    await db.refresh(payment)
    return payment, share_models
```

> **重要(Phase 4 実装時に観測):**
>
> - `source=PaymentSource.OCR if ocr_job else PaymentSource.MANUAL` の三項演算子を **必ず**書く。`source=PaymentSource.MANUAL` 固定のまま `ocr_image_path` だけ条件分岐にすると、source は manual だが画像 path だけ埋まるという矛盾状態になる。
> - 双方向 link `ocr_job.payment_id = payment.id` を **必ず**入れる(同一 tx 内、`db.flush()` で payment.id が populated された後)。これが無いと OcrJob 側の状態が更新されず、再送信した際の重複検知(`OcrJobAlreadyLinked`)が効かない。

> **検証順序の意図:** メンバー検証 → OCR 検証 → INSERT。OCR 検証を先にすると、share 不正なリクエストでも 400(OCR 系)が返って原因が見えにくくなる。share/member の整合は意味的に基礎なので先に弾く。

1. **2 層分離(pure poller + hook)** — polling のループ本体は **React 非依存の純粋 async function**(`utils/poll-loop.ts`)に切り出す。hook は state とライフサイクルだけを担当。これで polling のロジックを **fake-timer や renderHook 抜き**で vitest 純関数テストでカバーでき、テストの不安定性を回避する。

2. **2s × 15 = 30s timeout**(設計書 §6.4.2) — `MAX_ATTEMPTS` で打ち切り、`timedOut` フラグを立てて UI で「再試行してください」を出す。無限ループ防止。

3. **Cleanup** — `useEffect` の cleanup で `cancel()` を呼び、unmount / jobId 変更で polling を確実に停止。`AbortSignal` ベースで実装(setTimeout を抱えない構造の方が漏れにくい)。

4. **ブランド規則(設計書 §12.3)** — upload 中 + polling 中(= AI 処理中)は `text-red` / `bg-red` で発色、それ以外は `text-ink`。エラー警告は `border-l-2 border-ink`(editorial left-rule、`--red` は使わない)。

5. **エラー 2 種の区別** —
   - (a) クライアント側の MIME / サイズ違反は **upload を発行する前にブロック**(無駄なリクエスト・課金を防ぐ)
   - (b) サーバ側 `OCRFailed` は `status: failed` として polling で取得 → `errorMessage` を表示

6. **`onSucceeded` callback**(succeeded 時のみ呼ぶ) — 親(`OcrConfirmForm` を含む dashboard、Task 11)へ `OcrJobResponse` を渡す。失敗 / timeout は本コンポーネント内で完結(retry できる UI を出す)。

7. **kubb 生成型を直接使わない薄ラッパ** — `features/ocr/api.ts` で `uploadReceipt(groupId, memberId, file)` / `getOcrJob(jobId)` の関数シグネチャを定義。生成物の長い関数名(`uploadReceiptApiGroupsGroupIdOcrUploadPost`)を呼び出し側に漏らさない(`features/payments/api.ts` と同じパターン)。

```typescript
// frontend/features/ocr/utils/poll-loop.ts
import type { OcrJobResponse } from '@/features/ocr/api';

export type PollOptions = {
  jobId: string;
  fetcher: (jobId: string) => Promise<OcrJobResponse>;
  onUpdate: (job: OcrJobResponse) => void;
  intervalMs?: number;
  maxAttempts?: number;
  signal?: AbortSignal;
};

export type PollOutcome =
  | { kind: 'completed'; job: OcrJobResponse } // succeeded | failed どちらも completed
  | { kind: 'timed_out'; lastJob: OcrJobResponse | null }
  | { kind: 'aborted' };

const DEFAULT_INTERVAL_MS = 2000;
const DEFAULT_MAX_ATTEMPTS = 15; // 2s × 15 = 30s

/**
 * OcrJob の状態を定期取得し、`succeeded` / `failed` で終了する純粋関数。
 *
 * - 1 回目は **即時** fetch(待たない)→ 既に終わっている job を即座に返せる
 * - 以降は `intervalMs` 間隔
 * - `maxAttempts` で打ち切り → `timed_out`
 * - `signal.abort()` で中断 → `aborted`
 *
 * React に依存しないので vitest で素直にテストできる。
 */
export async function pollOcrJob(opts: PollOptions): Promise<PollOutcome> {
  const intervalMs = opts.intervalMs ?? DEFAULT_INTERVAL_MS;
  const maxAttempts = opts.maxAttempts ?? DEFAULT_MAX_ATTEMPTS;
  let lastJob: OcrJobResponse | null = null;

  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    if (opts.signal?.aborted) return { kind: 'aborted' };
    if (attempt > 0) {
      // wait は abort で即解除できる作りにする
      const aborted = await sleepWithAbort(intervalMs, opts.signal);
      if (aborted) return { kind: 'aborted' };
    }
    const job = await opts.fetcher(opts.jobId);
    if (opts.signal?.aborted) return { kind: 'aborted' };
    lastJob = job;
    opts.onUpdate(job);
    if (job.status === 'succeeded' || job.status === 'failed') {
      return { kind: 'completed', job };
    }
  }
  return { kind: 'timed_out', lastJob };
}

function sleepWithAbort(ms: number, signal?: AbortSignal): Promise<boolean> {
  return new Promise((resolve) => {
    if (signal?.aborted) {
      resolve(true);
      return;
    }
    const timer = window.setTimeout(() => {
      signal?.removeEventListener('abort', onAbort);
      resolve(false);
    }, ms);
    const onAbort = () => {
      window.clearTimeout(timer);
      resolve(true);
    };
    signal?.addEventListener('abort', onAbort, { once: true });
  });
}
```

```typescript
// frontend/features/ocr/use-ocr-job-poll.ts
'use client';

import { useEffect, useState } from 'react';
import { getOcrJob, type OcrJobResponse } from '@/features/ocr/api';
import { pollOcrJob } from '@/features/ocr/utils/poll-loop';

export type OcrPollState = {
  /** 最新の job 状態(なければ null = 未取得 or 未開始)。 */
  job: OcrJobResponse | null;
  /** 進行中(pending / processing 中)。UI で `--red` を発色するスイッチに使う。 */
  isPolling: boolean;
  /** 30s 経っても succeeded / failed に到達しなかった。 */
  timedOut: boolean;
  /** 通信エラー(404 含む。failed ステータスはここではなく `job.errorMessage`)。 */
  fetchError: string | null;
};

export function useOcrJobPoll(jobId: string | null): OcrPollState {
  const [job, setJob] = useState<OcrJobResponse | null>(null);
  const [timedOut, setTimedOut] = useState(false);
  const [fetchError, setFetchError] = useState<string | null>(null);

  // jobId 変更を検出して render 中に state をリセット(React 公式パターン
  // "Storing information from previous renders"):
  //   https://react.dev/reference/react/useState#storing-information-from-previous-renders
  // - useEffect 内で同期的に setState すると lint(no-setstate-in-effect 系)に引っかかる
  // - render 中の setState は同フレーム内で React がまとめて処理し追加 commit は発生しない
  const [prevJobId, setPrevJobId] = useState(jobId);
  if (prevJobId !== jobId) {
    setPrevJobId(jobId);
    setJob(null);
    setTimedOut(false);
    setFetchError(null);
  }

  useEffect(() => {
    if (!jobId) return;
    const ctrl = new AbortController();

    void (async () => {
      try {
        const out = await pollOcrJob({
          jobId,
          fetcher: getOcrJob,
          onUpdate: (j) => setJob(j),
          signal: ctrl.signal,
        });
        if (ctrl.signal.aborted) return;
        if (out.kind === 'timed_out') setTimedOut(true);
      } catch (e) {
        if (ctrl.signal.aborted) return;
        setFetchError(e instanceof Error ? e.message : String(e));
      }
    })();

    return () => ctrl.abort();
  }, [jobId]);

  const isPolling =
    job !== null && (job.status === 'pending' || job.status === 'processing') && !timedOut && !fetchError;

  return { job, isPolling, timedOut, fetchError };
}
```

> **`AbortController` を使う理由:** `setTimeout` を抱えるパターンより漏れにくい(`pollOcrJob` 内で `signal.aborted` を都度チェック + sleep を `addEventListener('abort')` で即解除)。jobId 変更や unmount で確実に停止する。

> **state リセットを `useEffect` 内に書かない理由(Phase 4 実装時に観測):**
>
> ESLint(`react-hooks/exhaustive-deps` 派生ルール / `no-setstate-in-effect`)が「effect 内の同期的 setState」を警告する。さらにこの書き方は **無駄な commit が 1 回増える**(effect が走ってからリセット → 旧データで render される瞬間がある)。
>
> React 公式の「Storing information from previous renders」パターンを採用すると:
> - render 中の `setX(newVal)` は React 内部で fast-path 処理され、**同じ render の続きに反映される**
> - 旧データで描画される瞬間が無くなる(UI が一瞬古い `timedOut`/`fetchError` を見せる現象を回避)
> - effect は純粋に「polling を開始する」責務だけになる
>
> `api.ts` 側で `OcrJobResponse` / `OcrUploadResponse` を再 export しておくと `@/features/ocr/api` 一本でモジュール境界を閉じられる。

> - **エラー / timeout の retry 動線**:`↻ もう一度試す` を `border-2 border-ink` ボタンとして明確に提示(従来の `underline` より発見しやすい)。`UploadFeedback` 1 component で `kind: 'failed' | 'timedOut' | 'error'` の 3 種を吸収。

```tsx
export const ALLOWED_IMAGE_TYPES = ['image/jpeg', 'image/png', 'image/webp'] as const;
export const ALLOWED_IMAGE_ACCEPT = ALLOWED_IMAGE_TYPES.join(',');
export const MAX_IMAGE_BYTES = 10 * 1024 * 1024;

export function validateImageFile(file: File): { reason: string } | null {
  if (!(ALLOWED_IMAGE_TYPES as readonly string[]).includes(file.type)) {
    return { reason: `対応していない形式:${file.type || '不明'}` };
  }
  if (file.size > MAX_IMAGE_BYTES) {
    const mb = (file.size / 1024 / 1024).toFixed(1);
    return { reason: `画像が 10MB を超えています(${mb}MB)` };
  }
  return null;
}
```

```tsx
'use client';
import { useEffect, useState } from 'react';

export function useElapsedSeconds(active: boolean): number {
  const [seconds, setSeconds] = useState(0);
  // active の on/off を render 中の prev 比較で検出してリセット
  const [prevActive, setPrevActive] = useState(active);
  if (prevActive !== active) {
    setPrevActive(active);
    setSeconds(0);
  }
  useEffect(() => {
    if (!active) return;
    const startedAt = Date.now();
    const timer = window.setInterval(() => {
      setSeconds(Math.floor((Date.now() - startedAt) / 1000));
    }, 250);
    return () => window.clearInterval(timer);
  }, [active]);
  return seconds;
}
```

```tsx
'use client';
import { useEffect, useRef, useState } from 'react';

import { uploadReceipt, type OcrJobResponse } from '@/features/ocr/api';
import { useElapsedSeconds } from '@/features/ocr/use-elapsed-seconds';
import { useOcrJobPoll } from '@/features/ocr/use-ocr-job-poll';
import { ALLOWED_IMAGE_ACCEPT, validateImageFile } from '@/features/ocr/utils/validate-image-file';
import { UploadActions } from './upload-actions';
import { UploadFeedback } from './upload-feedback';
import { UploadHeader, type UploadStatus } from './upload-header';
import { UploadProgress } from './upload-progress';

type Props = {
  groupId: string;
  memberId: string;
  onSucceeded: (job: OcrJobResponse) => void;
};

export function ReceiptUpload({ groupId, memberId, onSucceeded }: Props) {
  const cameraInputRef = useRef<HTMLInputElement>(null);
  const fileInputRef = useRef<HTMLInputElement>(null);
  const [jobId, setJobId] = useState<string | null>(null);
  const [uploadError, setUploadError] = useState<string | null>(null);
  const [isUploading, setIsUploading] = useState(false);

  const poll = useOcrJobPoll(jobId);

  // succeeded を 1 度だけ親へ通知(同じ job_id で重複しない)
  const succeededRef = useRef<string | null>(null);
  useEffect(() => {
    if (poll.job?.status === 'succeeded' && succeededRef.current !== poll.job.id) {
      succeededRef.current = poll.job.id;
      onSucceeded(poll.job);
    }
  }, [poll.job, onSucceeded]);

  const failed = poll.job?.status === 'failed';
  const isAiActive = isUploading || poll.isPolling;
  const elapsedSec = useElapsedSeconds(isAiActive);

  const status: UploadStatus = isUploading
    ? 'uploading'
    : poll.isPolling ? 'processing'
      : failed ? 'failed'
        : poll.timedOut ? 'timedOut'
          : 'idle';

  const showActions = status === 'idle' && !uploadError;

  const handleFile = async (file: File) => {
    setUploadError(null);
    succeededRef.current = null;
    const v = validateImageFile(file);
    if (v) { setUploadError(v.reason); return; }
    setIsUploading(true);
    setJobId(null);
    try {
      const res = await uploadReceipt(groupId, memberId, file);
      setJobId(res.jobId);
    } catch (e) {
      setUploadError(e instanceof Error ? e.message : 'アップロードに失敗しました');
    } finally {
      setIsUploading(false);
    }
  };
  const handleRetry = () => { setJobId(null); setUploadError(null); succeededRef.current = null; };
  const triggerCamera = () => cameraInputRef.current?.click();
  const triggerFile = () => fileInputRef.current?.click();

  return (
    <section className={`border-2 transition-colors ${isAiActive ? 'border-red bg-red/5' : 'border-ink bg-paper'}`}>
      <UploadHeader status={status} elapsedSec={elapsedSec} />

      <div className="p-4">
        {showActions && <UploadActions onPickCamera={triggerCamera} onPickFile={triggerFile} />}

        {(status === 'uploading' || status === 'processing') && (
          <UploadProgress phase={status} elapsedSec={elapsedSec} />
        )}

        {status === 'failed' && poll.job && (
          <UploadFeedback kind="failed" message={poll.job.errorMessage ?? 'OCR に失敗しました'} onRetry={handleRetry} />
        )}

        {status === 'timedOut' && (
          <UploadFeedback kind="timedOut" message="30 秒経っても完了しませんでした。" onRetry={handleRetry} />
        )}

        {uploadError && !isAiActive && (
          <UploadFeedback kind="error" message={uploadError} onRetry={handleRetry} />
        )}

        {poll.fetchError && (
          <p role="alert" className="mt-3 border-l-4 border-ink pl-3 py-1 font-jp-display text-xs">
            状態取得に失敗しました:{poll.fetchError}
          </p>
        )}
      </div>

      {/* Hidden inputs(ref から trigger):capture 付き(カメラ)と付かない(gallery) */}
      <input ref={cameraInputRef} type="file" accept={ALLOWED_IMAGE_ACCEPT} capture="environment" hidden
        onChange={(e) => { const f = e.target.files?.[0]; e.target.value = ''; if (f) void handleFile(f); }} />
      <input ref={fileInputRef} type="file" accept={ALLOWED_IMAGE_ACCEPT} hidden
        onChange={(e) => { const f = e.target.files?.[0]; e.target.value = ''; if (f) void handleFile(f); }} />
    </section>
  );
}
```

> **ブランド規則の適用:**
>
> - `--red` は **AI 能動状態のみ**(`isAiActive` = UPLOADING + PROCESSING)で section border / bg / header text / step dots / progress bar に適用。FAILED / TIMED OUT は AI 起動状態ではないので **ink ベースに戻す**(editorial left-rule 警告)。
> - 通知ステータスは `text-red` の経過秒タイマー + step dots アニメーション。動的な信号で「いま AI が働いている」を強く伝える。
> - エラー表示は `border-l-4 border-ink`(墨色)+ キッカーラベル(FAILED / TIMED OUT / ERROR)。`--red` は使わない。

> **タイポ主役 + emoji 脇役の意図:**
>
> - SVG 線画(`stroke-width="2"`)は brutalist にしては重く、ボタンの視覚的主役を奪う。SPLAI editorial は **タイポを主役にすべき**。
> - 📷 / 📁 を `text-base` / `text-sm` で右上に置くと、OS 標準フォントの自然なサイズで描画され**自前 SVG より自然に小さく**収まる。
> - 非対称レイアウト(左下にタイポ、右上に emoji)が editorial / brutalist のリズム。

> **`succeededRef` の意図:** `useOcrJobPoll` は再 render のたびに同じ job を返すため、素朴に `useEffect(() => onSucceeded(...), [poll.job])` だと **何度も** callback が走る。ref で「この job_id では既に通知済み」を覚えておく。jobId 切り替え時に reset。

```typescript
// frontend/features/ocr/utils/is-already-linked-error.ts
import { AxiosError } from 'axios';

/**
 * `createPayment` が投げたエラーが「OcrJobAlreadyLinked(409)」かを判定する。
 *
 * Backend は ProblemDetail JSON(`{ type, title, status, detail }`)を 409 で返す。
 * 同じ ocrJob を 2 度送信した場合のみ発生し、ユーザー視点では「既に登録済み =
 * 成功」と等価。OcrConfirmForm はこれを成功 path に昇格させて確認画面を閉じる。
 */
export function isOcrJobAlreadyLinkedError(error: unknown): boolean {
  if (!(error instanceof AxiosError)) return false;
  if (error.response?.status !== 409) return false;
  const body = error.response.data as { type?: string } | undefined;
  return typeof body?.type === 'string' && body.type.endsWith('/ocr-job-already-linked');
}
```

```tsx
      {/* ... header */}
      <section className="flex flex-col gap-4">
        <div className="flex gap-2">
          {(['form', 'chat', 'ocr'] as const).map((t) => (
            <button
              key={t}
              onClick={() => switchTab(t)}
              className={`font-mono text-xs px-2 py-1 ${
                tab === t ? 'bg-ink text-paper' : 'border border-ink'
              }`}
            >
              {t === 'form' ? 'FORM' : t === 'chat' ? 'AI CHAT' : 'OCR'}
            </button>
          ))}
        </div>

        {tab === 'form' && (
          <PaymentForm
            groupId={groupId}
            memberId={memberId}
            members={data.members}
            onCreated={onChange}
            draft={draft ?? undefined}
          />
        )}

        {tab === 'chat' && (
          <PaymentChat
            groupId={groupId}
            members={data.members}
            onDraft={(d) => {
              setDraft(d);
              setTab('form');
            }}
          />
        )}

        {tab === 'ocr' && (
          <div className="flex flex-col gap-4">
            <ReceiptUpload
              groupId={groupId}
              memberId={memberId}
              onSucceeded={setOcrDraft}
            />
            {ocrDraft && (
              <OcrConfirmForm
                groupId={groupId}
                memberId={memberId}
                members={data.members}
                draft={ocrDraft}
                onCreated={handleOcrCreated}
                onCancel={() => setOcrDraft(null)}
              />
            )}
          </div>
        )}

        {/* PaymentList / SettlementView / ShareSection は変更なし */}
      </section>
    </main>
  );
}
```

> **タブ切替時の `ocrDraft` リセット:** 「OCR で撮影 → 確認画面 → AI CHAT タブに移動 → OCR タブに戻る」したときに古い draft が残ると混乱する。tab 遷移で `setOcrDraft(null)` する。

> **登録成功時に form タブへ戻す:** OCR 経路は「単発の登録動作」が完結したら手動 FORM ホームに帰す方が UX 的に自然。再度撮影したいユーザーは OCR タブを押し直す。
